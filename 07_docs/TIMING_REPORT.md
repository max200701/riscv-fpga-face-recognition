## 实现与调整

计算和供数路径采用寄存分段，控制与存储按连接关系局部组织；跨时钟域路径按实际端点施加有限约束。

最后一次调整针对 DDR ODT 路径：保留原延迟缓冲，局部重布缓冲前后的通路。该端点的 setup 裕量由 −0.092 ns 提高到 +0.014 ns，数据连线延迟减少 0.106 ns，fast hold 裕量保持 +0.083 ns。整机当前最小 setup 裕量 +0.002 ns 位于另一条 RAS 路径。

这次调整保持逻辑连接、单元位置、时钟及约束一致，应用周期和 DDR 搬运量相同。综合映射资源为 80,469 LUT、76,412 FF、344 DRM、394 APM。

## 报告与实现文件

GitHub 仓库中的两份大报告以 `.xz` 保存；在仓库根目录执行 `python tools/extract_timing_reports.py` 后得到下表中的原始文件。

| 文件 | 内容 |
|---|---|
| `timing/QO/max/mini_face_demo_top.rtr` | 最大延迟原始报告 |
| `timing/QO/min/mini_face_demo_top.rtr` | 最小延迟原始报告 |
| 各目录的 `SUMMARY_FIRST_500_LINES.txt` | 原报告前 500 行，便于快速查看 |
| 各目录的 `report_db` | 时钟、检查项和端点汇总 |
| `QO_TIMING_EVIDENCE.json` | 时序与实现核对结果 |
| `timing/QO/REPORT_IDENTITY.json` | 原始报告、路由数据库和位流的 SHA256 对应关系 |

原始报告的详细路径数量设置为 `max_path=30000`。大报告适合按关键词搜索，日常查看可先打开摘要和汇总文件。

配套路由数据库为 `08_bitstreams/QO/routed.adf`，位流和 FIC 位于同一目录。重新分析的命令见 [构建与运行](BUILD_AND_RUN.md)。

## 接口覆盖范围

本报告覆盖已加载约束下的内部及接口路径。最差 setup 裕量较小，使用时保持上述时钟配置。`check_timing` 列出 63 个无 input_delay 端口和 76 个无 output_delay 端口，涉及外部及异步接口；外部 HDMI 器件与板级延迟的全工况覆盖仍需板级验证。
